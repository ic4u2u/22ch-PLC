상황별 테스트 방법 선택하기

지금 내 상황에 맞는 탭을 눌러 순서대로 따라 하세요.

방법 1-A · 대시보드 전체 체험

웹 관제 화면 & 22채널 시뮬레이션

  1. 프로젝트 폴더에서 통합 실행 명령 실행:
    npm run dev:all
  2. 브라우저에서 http://localhost:3000/?view=control 열기
  3. 상단 [관리자 PIN 잠금] 클릭 → 1234 입력 후 밸브 개폐, 영점 보정, 기밀 시험, 보고서 인쇄 기능 자유롭게 테스트
  4. 대형 TV용 화면은 http://localhost:3000/?view=wallboard에서 확인
방법 1-B · 통신 패킷 단독 연습

혼자서 XGT 통신 테스터 돌려보기

  1. tools/xgt-ethernet-tester/ 폴더 열기
  2. 1_PC_A_서버실행(가상PLC).bat 더블클릭 → TCP 2004 대기 확인
  3. 2_PC_B_클라이언트실행(EnetClient).bat 더블클릭 → 브라우저(http://localhost:3100) 자동 열림
  4. IP 127.0.0.1, 포트 2004 그대로 [연결] → [읽기 요청] 클릭해 %MW0 값(486 = 48.6)과 HEX 패킷 확인
PC 2대 · 같은 와이파이/공유기 또는 랜선 직결

현장 가기 전 다른 PC와 이더넷 통신 예행연습

  1. 두 PC 연결: 같은 공유기(와이파이/허브)에 연결하거나 랜선으로 1:1 직결(직결 시 PC A 192.168.1.10, PC B 192.168.1.11 수동 IP 설정)
  2. PC A (가상 PLC 역할): tools/xgt-ethernet-tester/1_PC_A_서버실행(가상PLC).bat 실행 → Windows 방화벽 팝업이 뜨면 [액세스 허용] 클릭 → 검은 창에 표시된 PC A의 IPv4 주소 확인
  3. PC B (현장 노트북 역할): 2_PC_B_클라이언트실행(EnetClient).bat 실행 → 대상 IP에 PC A의 IP 주소, 포트 2004 입력 → [연결] 후 읽기/전송 테스트
현장 실물 PLC (LS XGB + XBL-EMTA)

실물 PLC 연결 시 꼭 기억할 2가지 방식

① 1분 통신 확인 (XGT 테스터)

대시보드 설정 없이 "PLC와 통신이 되는지"만 가장 빠르게 확인할 때 사용합니다.
2_PC_B_클라이언트실행(EnetClient).bat 실행 → 현장 PLC IP(예: 192.168.0.50), 포트 2004 연결 → %MW100 읽기!

② 22채널 대시보드 실물 연동

.env.local에서 PLC_IP=192.168.0.50, PLC_PROTOCOL=XGT(또는 MODBUS)로 맞추고 가상 PLC(sim:plc)는 끈 채로 브릿지(npm run sim:bridge)와 웹(npm run start)만 실행합니다.

네트워크
1) 원클릭 배치 파일 2개 실행 (우클릭 → 관리자 권한)
  • set-plc-ip.bat : PC 고정 IP 192.168.0.100, 서브넷 255.255.255.0, 게이트웨이 비움 자동 설정
  • allow-firewall.bat : 포트 3000, 4000, 502, 2004, 8502 방화벽 허용
2) 명령 프롬프트(CMD)에서 Ping 테스트
ping 192.168.0.50

TTL=... 시간<1ms가 나오면 PC와 PLC가 네트워크로 정상 연결된 것입니다.

PLC 설정

PLC 엔지니어(XG5000) 측에서 XGT 전용 서버(TCP 2004) 또는 Modbus TCP 서버(TCP 502, Unit ID 1)가 켜져 있고 아래 번지를 사용하는지 확인하세요.

구분 LS XGT 번지 (TCP 2004) Modbus Holding Reg (TCP 502) 값 규칙
22채널 압력 (읽기) %MW100 ~ %MW121 Offset 0 ~ 21 (22 Words) 실제 압력(bar) × 10 (예: 1200 = 120.0 bar)
22채널 밸브 (읽기/쓰기) %MW200 ~ %MW221 Offset 100 ~ 121 (22 Words) 0 = OPEN (개방) / 1 = SHUTOFF (차단)
수신 확인
A. XGT 테스터로 1번 채널(%MW100) 읽어보기

http://localhost:3100 → IP 192.168.0.50, 포트 2004 연결 → %MW100 입력 후 [읽기 요청].
안 되면 우측 하단 [카톡 전달용 로그 복사]를 눌러 개발자/담당자에게 바로 공유하세요.

B. 대시보드 브릿지 연결 상태 확인
http://localhost:4000/api/diagnostics

브라우저에서 열었을 때 "plcConnected": true와 응답시간(latencyMs)이 나오면 성공입니다.

안전 주의
현장 안전 수칙: 실제 특수가스가 흐르는 배관에서는 반드시 현장 담당자와 협의한 뒤, 테스트 가능한 예비/단일 채널 1개만 먼저 밸브 개폐를 시험하세요.
  • 대시보드(http://localhost:3000/?view=control) 우측 상단 [관리자 PIN 잠금] → 1234 입력
  • 테스트 채널에서 OPEN / SHUTOFF 클릭 → PLC %MW200~%MW221 값이 0 ↔ 1로 바뀌고 실물 밸브가 작동하는지 확인
  • 압력 오차가 있으면 채널 설정(⚙️)에서 ±0.1 bar 오프셋 보정 또는 가스 미공급 상태에서 0점(Zero) 설정 실행

자주 막히는 문제 & 해결 방법 (FAQ)

          
현장에서 오류가 나면 아래 항목을 먼저 눌러 확인하세요.

        

      

      

        

          1. ping 192.168.0.50 이 실패(요청 시간이 만료되었습니다)합니다.
          

            ① 랜선이 공유기 포트(LAN 2)가 아니라 PLC 직결 포트(LAN 1)에 꽂혀 있는지 확인하세요.

            ② Windows 어댑터 이름이 이더넷이 아니면 set-plc-ip.bat 안의 ADAPTER_NAME을 수정하거나, 제어판 → 네트워크 어댑터에서 직접 IP 192.168.0.100 / 서브넷 255.255.255.0을 입력하세요.

            ③ 현장 PLC IP가 192.168.0.50이 아닌 다른 IP(예: 192.168.1.10)로 되어 있을 수 있으니 PLC 담당자에게 IP를 확인하세요.
          

        

        

          2. Ping은 되는데 연결이 안 됩니다 (ETIMEDOUT / ECONNREFUSED).
          

            ① allow-firewall.bat를 우클릭 → 관리자 권한으로 실행했는지 확인하세요.

            ② XG5000에서 XGT 서버(2004) 또는 Modbus TCP 서버(502)가 체크되어 있고 PLC에 다운로드/리셋 반영이 되었는지 확인하세요.

            ③ .env.local의 PLC_PROTOCOL과 실제 PLC에 켜진 프로토콜이 서로 맞는지(XGT↔2004, MODBUS↔502) 확인하세요.
          

        

        

          3. 연결은 됐는데 압력이 0 bar 또는 보라색 SENSOR_FAULT로 뜹니다.
          

            ① PLC가 %MW100~%MW121에 실제 압력 × 10 (예: 120.0 bar → 1200) 형태로 값을 넣고 있는지 확인하세요.

            ② 4~20mA 센서 선이 빠졌거나 0 미만 / 측정 한계 초과 값이 들어오면 안전을 위해 보라색 SENSOR_FAULT로 표시하고 오작동을 막습니다.
          

        

        

          4. 대시보드에서 밸브 버튼을 눌러도 움직이지 않습니다.
          

            ① 화면 상단 [관리자 PIN 잠금]이 풀려 있는지(PIN 1234, 5분 타이머) 확인하세요.

            ② 예비 통이 비어 있는 상태에서 자동 절체를 시도하면 안전 인터록이 빈 통 절체를 차단합니다.
