1단계

현장 도착 후 랜선 연결 & IP 맞추기 (가장 중요!)

  • 랜선 연결 & PLC 정보 확인 — 내 PC와 PLC(또는 현장 허브)를 랜선으로 연결하고, 현장 담당자에게 PLC IP 주소와 통신 방식을 확인합니다.
    예: 192.168.0.4 / LS XGT (TCP 2004번 포트)
  • 내 PC IP를 PLC와 같은 대역으로 맞추기
    예) PLC IP가 192.168.0.4 라면 → 내 PC 유선 랜 IP는 192.168.0.100, 서브넷 마스크 255.255.255.0 으로 고정 설정
  • Ping 테스트로 물리 연결 확인 — Win + R → cmd 실행 후 아래 명령 입력
    ping 192.168.0.4
    ✅ 응답: 바이트=32 시간<1ms ... 가 나오면 연결 성공! ("요청 시간이 만료되었습니다"가 뜨면 IP 대역/랜선 재확인)

    ② 통신 방식: 1 (LS XGT 전용 프로토콜 · TCP 2004)
    ③ 현장 PLC IP 입력: 확인한 IP 입력 (예: 192.168.0.4) 후 엔터

3단계

22워드 통신 정상 여부 확인 (핵심 체크포인트)

  • 덤프 모니터 탭 이동 & 연결 확인
    상단 탭에서 [📡 PLC TX/RX 패킷 덤프] 클릭 → 통신 상태가 🟢 연결됨 (정상 수신) 인지 확인합니다.
  • 1회 단발 요청으로 TX / RX 패킷 확인
    ① [⏸️ 0.5초 자동수신 중 (일시정지)] 버튼 클릭 → 일시정지 상태로 전환
    ② [📥 22워드 압력 즉시 요청 (TX)] 버튼 1번 클릭
    ✅ 정상 수신 기준
    • TX: 38 Bytes (54 00 14 00 ... 25 4D 42 32 30 30 2C 00)
    • RX: 76 Bytes (55 00 14 00 ... 2C 00 + 44바이트 데이터)
    • 숫자: Word 1~22가 PLC 원시값 ÷ 10 (bar) 로 일치
    ⚠️ 비정상 주의 (1워드만 올 때)
    • RX가 76B가 아니라 34 Bytes이고, 중간에 55 00 02 00 이 찍히면 1워드(2바이트)만 응답한 상태!
    • 현장 PLC 담당자에게 "%MB200 연속 읽기(44바이트) 응답" 설정을 확인 요청하세요.
  • 실시간 연동 복귀 — 확인 후 [▶️ 일시정지됨 (클릭 시 재개)] 버튼을 다시 눌러 0.5초 자동수신으로 돌아와 대시보드 게이지가 정상 표시되는지 확인합니다.
4단계

결과 공유 및 문제 발생 시 10초 해결법

📋 결과 공유 / 이상 증상 문의 방법:
화면 상단 [📋 카톡 전달용 덤프 복사] 버튼을 누르면 파일로 저장되는 게 아니라 클립보드에 복사됩니다. 그대로 카톡방에 붙여넣기(Ctrl + V)해서 보내주시면 바로 분석해 드립니다!
Q1. 🔴 연결 안 됨 / 응답 시간 초과(타임아웃)가 뜹니다.
1) cmd에서 ping <PLC_IP>가 통하는지 먼저 확인하세요.
2) PLC 쪽 XGT 전용 프로토콜 서버(TCP 2004 포트)가 켜져 있는지 확인하세요.
3) Windows 방화벽이 막고 있으면 폴더 안의 allow-firewall.bat를 우클릭 → 관리자 권한으로 실행하세요.
Q2. RX가 76 Bytes가 아니라 34 Bytes로 오고 Word 1~22가 전부 0.0 bar입니다.
PLC가 연속 읽기(14 00) 요청에 대해 22워드(44B)가 아닌 단일 워드(02 00, 2B)만 응답하고 있는 상태입니다. 현장 PLC 담당자와 통신 설정(XGT 연속 읽기 지원 여부 및 %MW100~%MW121 데이터 할당 여부)을 확인하세요.
Q3. 화면 압력 숫자가 실제보다 10배 크거나 작게 나옵니다.
약속된 규격은 PLC 원시 정수 = 실제 압력(bar) × 10 입니다.
• 예: 148.0 bar → PLC에 정수 1480 (0x05C8) 저장
• 예: 23.4 bar → PLC에 정수 234 (0x00EA) 저장
